STFU - plan prac wydajnosci CPU/GPU/DX11
========================================

Cel
---
Ten dokument jest roboczym planem implementacji dla kolejnych patchy. `src/concat.txt`
traktujemy jako indeks i zrzut referencyjny kodu z dnia 2026-06-06, ale wszystkie
zmiany robimy recznie w prawdziwych plikach repo.

Glowny cel techniczny: zmniejszyc realny frame time i poprawic responsywnosc UI.
Nie probujemy sztucznie wypelnic CPU do 100 procent. Przy 16 workerach okolo 30
procent CPU moze byc normalne, jezeli pipeline czeka na GPU, readback, present,
albo jest ograniczony pamiecia lub sekwencyjna czescia algorytmu.

Zasady dla wszystkich patchy
----------------------------
1. Nie dodawac `Parallel.For`, `Task.Run`, `Thread` w hot path NPR/renderingu.
   Uzywac `STFU.Parallelism.DeterministicParallel.ForRanges`.
2. Wynik rownolegly musi miec deterministyczny order. Range-local append, potem
   merge po `rangeIndex`.
3. W hot loopach nie robic `Interlocked` per pixel/per sample/per segment.
   Liczniki zbierac lokalnie i scalac po zakresie lub po kaflu.
4. Po kazdej zmianie hot path uruchamiac parity dla workerow 1/2/4/8, a przy
   wiekszych zmianach takze 12/16/24.
5. Dla DX11 rozrozniac CPU wall time i prawdziwy GPU time. `Stopwatch` wokol draw
   nie jest GPU timingiem.
6. Viewport direct path ma unikac GPU readback. Readback tylko eksport, testy,
   parity, debug lub jawny tryb ustawiony przez uzytkownika.
7. Najpierw zmniejszac ilosc pracy i alokacje, potem dopiero podnosic worker count.
8. Nie zmieniac domyslnych workerow/tile size bez benchmark sweep.
